# 单指标工作流决策记录

## 已确认的结论

| 结论 | 理由 |
|---|---|
| 四条单链以 `1_优化源码/source_code` 的生成实现和配置作为共同基线；单链只保留各自的指标评审模块。 | 避免四条链从不同的生成底座出发，确保调优结果可以比较和回合并。 |
| 每轮只调整当前指标对应的生成提示或逻辑；固定评审规则、权重和模型配置。 | 把分数变化归因到生成侧改动，避免评审标准移动。 |
| 每轮生成四篇候选文章并交叉运行四项评审。实现口径为12个逐篇内容分，加1个整组格式分。 | 检查目标和其他指标；格式按四篇与ZIP整组评价，不重复计入平均。 |
| “优化源码”当前四篇文章作为固定基线，独立留存快照。 | 改动前后使用同一基准，避免样本变化干扰比较。 |
| 目标指标以四篇平均分提升至少5个百分点为门槛；其他指标平均降幅不超过5个百分点；不得出现新增严重事实或内容问题，硬性检查须全部通过。 | 给每轮提供明确、可复核的通过条件。 |
| 格式基线已为10/10，后续保持满分，并检查错误格式能被拦截；不再要求该项额外提升5个百分点。 | 用户确认的满分例外，避免为制造分差改变评审尺度。 |
| 四条单链分别调优后，最终把确认有效的改动合并进“优化源码”总源码。 | 保留指标专属迭代空间，最终形成统一版本。 |

## 已修复的基线阻断问题

科学准确性长材料评审在调用语义检索时漏传模型客户端，导致文章进入评审前抛出 `TypeError`。四条链的离线检索与在线准确性检索现在分别调用正确的函数签名，评分提示和扣分规则保持不变；回归测试覆盖客户端传递与离线路径。Windows 命令行输出统一使用 UTF-8，避免原文特殊字符中断报告。

完整性初版的24条分片要点会挤占长文证据预算，且六个不参与评分的额外摘录字段使真实引文整片失效。现允许模型每片最多返回24个候选，但本地仅依赖页码、类型、概括和连续原句校验；余下的抽取提示字段不进入评审。评审最多保留每片6条，超量或超出32000字符全局预算时，再用剩余的同一32次调用额度按候选原句压缩。预算按全文片段均分，并按实际送审文本计量。失败重试与压缩也计入32次总额度；修复仍失败、漏扫或超限均保留待核验，不能形成完整分数。

评审兼容“待核验项”字段，保留所有未核验事项并禁止以其形成完整分数。格式评审补充逐文件字数、来源匹配与ZIP读回检查证据。

真实调用中60秒网络等待连续超时，已增加独立的 `review.request_timeout=180`。模型、温度、输出上限、32000字符证据预算和32次取证上限不变。成功响应按输入与模型参数缓存，重跑仍执行证据校验；报告实时保存并附结构化JSON。
