# 四条单链的调优方式

## 共同基线

四条链的共享 `pipeline/*.py` 与 `1_优化源码/source_code/pipeline/` 一致，新增的 `criterion.py` 和 `single_review.py` 负责单项评审。`main.py` 的评审路由转向本链，其余生成、验收和打包逻辑与共同基线一致。

生成目标长度统一为1700字；模型、温度和输出上限统一。评审证据预算仍为32000字符、长文取证上限仍为每篇32次；`review.request_timeout=180` 只延长网络等待，不改变采样参数或扣分规则。

固定基线为 `workflow-benchmark/baseline/docs/` 四篇文章。四条链已载入同一批文章和原始PDF。已有文章的 manifest 保留原生成记录，不冒称是由单链重新生成的。

## 每轮操作

1. 选择一个目标指标，在对应单链调整生成提示或逻辑，保留本轮改动和理由。评审模板、权重与模型采样配置保持固定。
2. 在该链运行 `generate`，生成四篇候选文章；运行 `validate` 检查硬性要求。
3. 把同一组四篇候选稿和 `_manifest.json` 复制到四条链各自的 `docs/`。保留固定基线快照。不要把各链分别生成的四组文章当作同一轮交叉评估。
4. 格式链先运行 `package`，再分别运行四条链的 `review`。评审不改文章。四条链可以独立运行。
5. 四项都结束后，从仓库根运行 `tools/workflow_round.py check-format`，确认错误格式与损坏ZIP能被拦截；再运行 `tools/workflow_round.py collect <轮次名称>`。工具检查四项报告的文章指纹一致后保存本轮报告副本，已有轮次不覆盖。
6. 用 `compare baseline <轮次名称> --target <accuracy|expression|coverage|format>` 查看分数变化、评审配置一致性及失败项。

例如，在科学准确性工作流根目录中运行：

```powershell
py -3.14 -B source_code/main.py generate
py -3.14 -B source_code/main.py validate
py -3.14 -B source_code/main.py review
```

格式链的评审命令前需要执行：

```powershell
py -3.14 -B source_code/main.py package
```

## 评分和验收

科学准确性、科普表达、内容完整性各逐篇评估，共12个逐篇分数；格式规范性对四篇文章和ZIP统一评估一次，共1个整组分数。格式分不重复计入四篇平均。

各项先换算为百分比。目标指标的四篇平均值须提升至少5个百分点；其他指标平均降幅不得超过5个百分点。候选稿的格式与ZIP硬性检查必须通过，且需逐条核对没有新增严重事实或内容问题。

对比工具检查数值门槛、评审依赖/模型/原始材料是否固定，以及新增高风险标记。分数不完整时停止数值验收，不把缺失分数填零或按剩余文章计算平均。严重问题仍须结合具体引文审读，工具不会自动合并。

评审依赖若发生修复，须重新建立基线后比较。生成提示可以变；评审所依赖的 `generate.py` 引文校验等函数若改变，比较工具会提醒先确认评审口径，避免把验证器变化当成生成改进。

格式基线已为10/10。用户已确认该链按保持满分、错误格式能被拦截验收，不要求额外提升5个百分点。对比工具会检查当前验证器的负例回归记录，旧源码对应的检查记录不能替代当前版本。

## 运行记录和恢复

`review` 同时保存 Markdown 诊断报告与 JSON 结构化报告。JSON 记录文章、材料和评审代码指纹、模型配置、分数、待核验项及本轮是否具备完整分数。

完整性长文取证按全部片段分配证据预算，每片最多保留6个核心要点；检查原句和页码后再送审。首次扫描先覆盖全文，剩余调用额度用于失败重试与依据原句压缩，均计入32次上限。预算溢出、假引文、漏扫和空白页仍阻止完整评分。JSON保留实际送审证据与扫描记录，便于复核；运行期间文章、材料或评审源码变化也会使本次报告不完整。

请求进度实时输出，Markdown 报告边运行边保存。`source_code/result/review_cache/` 按文章编号、实际输入和模型采样参数保存成功响应；完全相同的请求重跑时复用响应，随后重新校验引文、字段与扣分算术。API密钥不进入缓存标识和报告。失败请求不缓存。

需要观察同一配置的新随机回复时，可以把 `review_cache/` 改名留存，再运行评审；不同文章、证据或模型参数会自然产生新的缓存键。

## 合并回总源码

准确性检索把全文分片扫描、错引定向重试和弱词汇候选补查计入每篇32次调用预算。重试优先只携带校验失败对应的主张；数字或弱词汇重合仍不算完成核验。扫描覆盖完整不代表每条主张已核实，待核验项仍会阻止完整评分。

通过验收的生成改动按指标保留清晰差异和理由，再合入 `1_优化源码`。最终合并版重新生成四篇并交叉评估，单项版本分别通过不能代替合并后的检查。

改前源码备份位于 `workflow-benchmark/pre-sync/`；该目录、评审缓存和文章快照只在本地保留，决策说明保存在本仓库的 `docs/` 中。
