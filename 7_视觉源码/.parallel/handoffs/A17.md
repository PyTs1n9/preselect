# A17 evidence schema 落盘交接

## 1. 背景与范围

B1 交付了 evidence 字段语义（`.parallel/B-FIELD-REQUEST.md` 答复区、`docs/B1_交付说明.md`）。
I3 规定字段语义由 B 定义、由 A 原样落盘。本卡把该片段落进 `schemas/evidence.schema.json`
并处理由此产生的连带破坏：工程夹具仍是"单条事实"形状，直接落盘会让 validate 与 packaging
两类测试同时变红。

范围只到"字段可校验、基线不降"。五项一致性检查（A14）、`recognition` / `document_ir`
的字段片段未在本卡内。

## 4. 副作用与未覆盖项

1. **`stats.evidence_count` 口径不变**（schema 合规的证据对象数，恒 0/1）。原因：
   `validation.schema.json` 1.1.0 的描述明确写的是"0/1 对象数"，改成事实条数属语义变更，
   需另升 1.1.1 并同步 A9 断言。引用数与未引用数仍为 0，由 A14 一并改。
2. **`block_id` 目前只能校验"非空字符串数组"**。`document_ir.blocks` 仍是空壳，
   无法断言该块真实存在。这是引用链唯一的断点，必须在 A10 真跑前由 B 补 IR 字段。
3. **B 的正式双签未补**。I3 的字段依据是 B1 答复，§12 中 I3 仍为 ☐；本卡不代签。
4. **`recognition` / `document_ir` 仍无 `schema_version`**，因此仍无版本门；
   它们一旦落盘，必须同步登记 `SUPPORTED_VERSIONS`，否则版本门静默失效。
