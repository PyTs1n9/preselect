## 4 未覆盖风险

- 引用覆盖、数值/单位一致性、串稿未实施，明确列入 checks.skipped。valid=true 只说明本轮已启用检查通过；不得解释为八类检查全过。
- 业务三个 schema 仍是 B 待补字段的基础版本，additionalProperties=true；本卡只调用统一加载器，没有自建业务 schema 或自创字段。
- 接口清单仍有待确认/未双签项；本卡基于用户明确授权消费现有工程契约，未代签或更新冻结文件。
- Markdown 处理为本卡所需的确定性子集（ATX/Setext 标题、围栏/缩进代码、链接、HTML 标签/注释），不是通用 CommonMark 渲染器。敏感信息覆盖选中 Markdown 的原文（含来源/元数据/代码/链接）；未扩展为其他日志或任意文件的全盘扫描。
- 现有 main.py 在正常返回 ValidationReport 时返回退出码 0，即使 valid=false。本卡按白名单未改 CLI；调用方需检查报告状态，CLI 退出码行为属于卡外事项。
- 共享 W0/1.1.0 内核在开始时已有未提交或未跟踪改动。本卡提交只包含 A9 文件，依赖的共享内核须由其 owner 集成；不能仅凭 A9 单个提交宣称干净检出可独立运行。

## 5 下游需知

- A11 使用结构化 issues，依 severity 判断，不能丢弃 warning；不得把 skipped 当作已通过。
- A15 打包需同时满足 valid=true 且 checks.skipped 为空；本轮工程合法样本的 skipped 非空，不能作为完整业务验收或打包合格凭据。
- B 交付事实列表、引用编号、core、数值/单位和正文 material_id 格式后，再独立确认启用第 5/6/8 项；本轮没有隐藏跳过开关或永远返回空结果的假检查。
- validation.json 为 UTF-8、无 BOM、LF 换行；写入和读回失败抛 IoFailure（退出码映射 7），报告 schema 自检失败抛 PipelineError(SCHEMA_INVALID，退出码映射 4)。错误消息不包含原文凭据或本机绝对路径。
- 运行单元测试不改工程夹具；任务卡单次验收会更新相应 fixture 的 validation.json（含 checked_at）。以上输出保留了本次验收证据。
