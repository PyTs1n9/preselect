## 2. 可复制签名

```python
write_draft(evidence_path: Path, ctx: RunContext) -> StageResult
repair_draft(draft_path: Path, validation_path: Path, ctx: RunContext) -> StageResult
_draft_payload(evidence: dict) -> dict

STAGE_NAME: str
REQUIRES: list[str]
PRODUCES: list[str]
run(ctx: RunContext, inputs: dict[str, Path]) -> StageResult
```

| 阶段 | STAGE_NAME | REQUIRES | PRODUCES | 成功文件 |
|---|---|---|---|---|
| 写作 | write | ["evidence"] | ["draft"] | draft.md |
| 修复 | repair | ["write"] | ["final"] | final.md |

- write/repair 均使用 json_schema=None、images=None、skill=None，正文取 ModelResult.text；阶段包装模块不重复记录 manifest。
- writer 请求 payload 只有 evidence。repair 请求只有当前 draft、error 级 issues 的 code/path/message/hint，以及 only_codes/preserve_unlisted_text/no_new_facts；每轮重新读取 draft。
- 0 轮：draft 已合格时，不加载 repair.md、不建立 provider、不产生 raw，仍写 final 并再次运行真实校验器。
- 1/N 轮：上限来自 settings.pipeline.max_repair_attempts；每次 provider 都经 generate_and_close 关闭；0 上限立即 REPAIR_EXHAUSTED/6，不加载 repair 提示词。
- 每轮先保存 raw/repair_<n>_diff.md 和 raw/repair_<n>_request.json，再做新增数值检查；空 diff 也落盘。request 不含 prompt_text，包含 stage/attempt/prompt_name/prompt_sha256/prompt_version/codes/model/attempts/request_hash。
- 新增事实检查只查看本轮 diff 的新增行，跳过 +++ 元数据，剥离 Markdown 结构序号，用卡片指定正则提取数字，归一化千分位并匹配数字边界。不检查实体。
- 新增数值命中时保留 raw，原 draft 不覆盖，REPAIR_INTRODUCED_FACT/6；N 轮耗尽时保留最后 draft 和每轮 raw，REPAIR_EXHAUSTED/6。
- 每轮修订后运行 validate_run；通过后写 final，再次 validate_run。final 复验失败则删除 final，抛 REPAIR_EXHAUSTED；draft 与失败证据保留。
- I6 现行报告没有顶层 path，成功时 issues 为空。测试以委托真实 Path.read_bytes 的读取记录证明最后一次校验实际读取 final.md，不添加任何 schema 字段；失败时 issues[].path 保留 final.md 定位。
