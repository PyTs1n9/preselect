## 2 可复制签名

```python
# pipeline/prompt_loader.py —— I4 资产边界
load_prompt(name: str, base_dir: Path) -> PromptAsset   # .text .sha256 .path .version
load_skill(path: Path) -> SkillAsset                    # .text .sha256 .path

# 阶段模块契约（orchestrator.discover_stages 只认这四个名字）
STAGE_NAME: str
REQUIRES: list[str]
PRODUCES: list[str]
run(ctx: RunContext, inputs: dict[str, Path]) -> StageResult
```

| 阶段 | REQUIRES | PRODUCES | 落盘文件（run_dir 内） |
|---|---|---|---|
| `recognize` | `[]` | `["recognition"]` | `input/page_%04d.png`、`input/source.pdf.sha256`、`recognition.json`、`manifest.json` |
| `normalize` | `["recognize"]` | `["document_ir"]` | `document_ir.json` |
| `evidence` | `["normalize"]` | `["evidence"]` | `evidence.json` |

行为契约（下游可依赖）：

- 源 PDF 不进 run 目录；经 `ctx.artifacts["source_pdf"]` 传入，`manifest.input = {path_name, sha256, page_count}`。
- 阶段间只通过磁盘传递：`normalize` 读 `recognition.json`、`evidence` 读 `document_ir.json`，均重新解析，不复用内存对象。
- 顺序由 `requires` 拓扑决定，`--stage all` 才会串行三阶段；单阶段只保证补齐其依赖。
- 资产缺失/空白/无版本：`ASSET_MISSING`（退出 8）/ `ASSET_EMPTY` / `ASSET_NO_VERSION`（warning，不失败）。
- 模型输出先落盘再校验；schema 不合法抛 `SCHEMA_INVALID`，但非法 JSON 已写入磁盘，**存在产物文件不等于阶段成功**。
- `manifest.stages[]` 每条为 `{name, status, started_at, ended_at, duration_ms, artifacts, issues, model_calls}`，`status ∈ running|ok|failed`；`failed` 必有 `issues[].code`。
- `model_calls[]` 每条含 `prompt_name`、`prompt_sha256`、`prompt_version`、`attempts`（失败时为 `null`，未编造重试次数），`recognize` 另含 `skill_sha256`。

## 4 风险与解除条件（按阻塞程度排序）

1. **正式 run 无法越过 recognize（阻塞 A10）**。`prompts/` 目录不存在，真实 run 必然停在 `ASSET_MISSING`/退出 8，`recognition.json` 及其后产物永远不会生成。解除条件：B 交付 `prompts/{vision,normalize,evidence}.md`，首行带 `<!-- version: x.y.z -->`，且 `skills/pdf-vision/SKILL.md` 就位；A10 再跑一次单页真实素材。
2. **三阶段从未做过真实联网贯通（阻塞 A10/A12）**。模型边界只以假 provider 验证，`model_calls.attempts`、真实 `recognition.json` 结构、真实 `document_ir.json`/`evidence.json` 均无实测样本。解除条件同第 1 条，并在 A10 记录每阶段 `model_calls` 与 `duration_ms`。
3. **非法模型输出会留下产物文件（影响 A12 判定口径）**。阶段先落盘再校验，`SCHEMA_INVALID` 抛出时非法 JSON 已在磁盘。下游若以「文件存在」判断成功会误判。解除条件：A12 打包前必须以 manifest `stages[].status == "ok"` 为门槛，而非文件存在性。
4. **manifest 只登记最终产物**。`input/page_*.png` 与 `input/source.pdf.sha256` 已落盘但不在 `manifest.stages[].artifacts` 内，按 manifest 清点产物会漏掉 I2 要求的 sha256 文件。解除条件：A10/A12 若需全量清点，改用目录遍历；如需登记，由 S0 裁决后改 `_shared.record_stage`。
5. **manifest 的端点信息被裁剪**。`config.vision.base_url` 只保留 `host:port`，无 scheme 与 path，追溯具体端点需另查 `config.json`。解除条件：I2 未要求完整 URL；如需要，由 S0 裁决。
6. **夹具目录与 run 发现规则耦合**。`tests/fixtures/engineering/` 下任何新目录只要不以 `run_` 开头，就必须保持 `glob("run_*")` 参数化，否则快照用例会收集到空目录。解除条件：已由本次 1 行改动固化，新增夹具沿用 `run_` 前缀。
7. **阶段失败码依赖 A7 的分类**。`AuthMissing`/`ModelTimeout`/`ModelRefused`/`TruncatedResponse`/`InvalidModelOutput` 由适配器抛出，阶段只透传并记入 issue；适配器改分类会直接改变退出码。解除条件：无（属既有契约）。

## 5 A10 / A12 下游需知

**A10（端到端，只跑不改）**

- 可用命令：`main.py run <pdf> --stage recognize|normalize|evidence|all`；默认输出 `result/runs/<material_id>/<run_id>/`（已被 `.gitignore` 的 `**/source_code/result/` 覆盖）。
- 预期退出码矩阵：`0` 全阶段成功；`8` `ASSET_*`（当前必然命中，见风险 1）；`2` `AUTH_MISSING`；`4` `validate --run-id` 校验不通过；`1` 未分类/注册表为空。
- 判定成功只看 `manifest.stages[].status`，不看文件是否存在。
- `evidence.json` 当前 schema 是单对象，`stats.evidence_count` 为 0/1，不是条数。
- 不要改 `stages/__init__.py`：自动发现按模块名排序，执行顺序由 `requires` 拓扑决定，改动会打乱两者的一致性假设。

**A12（打包）**

- 源 PDF **不在** run 目录内，只能从 `manifest.input.{path_name, sha256}` 反查原始素材。
- 打包前逐阶段核对 `status == "ok"` 与 `issues` 中无 `severity == "error"`。
- 三份产物文件名固定：`recognition.json`、`document_ir.json`、`evidence.json`，均在 run 根目录。
- manifest 内不含密钥；若新增字段，必须继续经 `_redact_values` 过滤，否则会打破本次的 `key_in_manifest = False` 证据。
