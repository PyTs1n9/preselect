## 1. 为什么现在卡住

`schemas/evidence.schema.json` 当前只声明了三个字段：

```json
{"page_number": "integer >= 1", "region": "object", "quote": "string"}
```

它是**单条事实**的形状，没有列表容器。而 I3 的表格写的是"事实列表，每条含
`page_number`、`block_id`、`quote`"——`block_id` 在文件里也没有。

A9 需要回答三个问题，现在的 schema 一个都回答不了：

1. 正文的 `[3]` 指的是 evidence 里的哪一条？（缺唯一标识）
2. 哪些事实是"必须被引用"的核心事实？（缺 core 标记）
3. 正文写"准确率 92.3%"时，怎么判断证据里支持的是同一个数、同一个单位？（缺数值与单位）

## 答复区

```text
## evidence 字段
facts_container:
① 取值/格式：顶层必须有 `facts` 数组；每项是一条事实对象，至少含 `fact_id`、`core`、`page_number`、`block_id`、`quote`、`value`、`unit`。② A 的确定性判定：根对象存在 `facts` 且为数组；逐项检查对象类型和必需键，拒绝把单条事实直接放在根部。③ 反例：`{"page_number":1,"quote":"只有一条散落事实"}` 没有 facts 容器，直接报结构不合格。
fact_id:
① 取值/格式：稳定字符串 `F001`、`F002`……，从 `F001` 连续递增，单份 evidence 内唯一。② A 的确定性判定：正则 `^F[0-9]{3,}$`，按整数部分排序后必须从 1 连续到 n，且无重复；正文引用只接受已存在 ID。③ 反例：`F001` 与 `F001` 重复，或从 `F003` 开始，或写成 `fact-1`。
core:
① 取值/格式：JSON 布尔值 `true`/`false`，每条事实显式填写。② A 的确定性判定：只把 `core == true` 的事实加入核心集合，不能根据数组顺序或正文位置猜测。③ 反例：用字符串 `"core"`、缺失 core，或约定“前五条自动算核心”。
value:
① 取值/格式：单值用 JSON number；多值用 number 数组；区间用 `{"min": number, "max": number}`；无数值事实用 `null`。负数和科学计数法按 JSON number 表达。② A 的确定性判定：按类型解析，拒绝 NaN/Infinity；区间要求 min≤max，多值按数组逐项比较。③ 反例：把 `80–90%` 塞进 number，或把 `1e3` 写成带单位的自由文本而没有 value_text。
unit:
① 取值/格式：单值用字符串，如 `%`、`mg/kg`、`倍`；多值用与 value 等长的字符串数组；无量纲事实使用 `"倍"` 或 `null`（若事实确实没有单位）。② A 的确定性判定：Unicode 空白折叠后逐字比较，复合单位按完整字符串比较，不拆分猜测。③ 反例：把 `mg/kg` 拆成 `mg`，或将 `85%` 的 unit 填成 `"比例"`。
block_id:
① 取值/格式：单块也统一用字符串数组，如 `["B003"]`；一条事实跨块时按源顺序列出全部块。② A 的确定性判定：数组非空、元素为非空字符串；与 page_number/region 的位置数组按索引对应。③ 反例：写成无法追溯的 `"正文"`，或跨两个块却只保留一个不确定块号。

## 正文元数据
material_id_position:
① 取值/格式：正文首个非空行必须是 `<!-- material_id: M1 -->`，ID 使用安全段 `[A-Za-z0-9._-]+`。② A 的确定性判定：只读取首个非空行并用 `^<!--\s*material_id:\s*([A-Za-z0-9._-]+)\s*-->$` 匹配，再与 manifest/evidence 的 material_id 精确比较。③ 反例：把 `material_id=M1` 写在普通段落，或写成 `<!-- material: M1 -->`。
title_and_sections:
① 取值/格式：随后必须有一个非空一级标题；章节标题逐字为一级标题 `# 引言`、`# 正文`、`# 总结`、`# 来源`，不得编号、前缀或变体。② A 的确定性判定：复用 `count_han` 的 Markdown 解析和现有四节逐字检查；来源节不计入正文汉字数。③ 反例：`## 引言`、`# 1. 引言`、`# 结论` 均不满足。
citation_and_sources:
① 取值/格式：正文引用写 `[F001]`；来源节每行写 `[F001] page=1 block=B003 quote=原文摘录`，一条事实可多次引用。② A 的确定性判定：正则提取正文中的 `F` 编号，与 facts 的 ID 集做集合检查；来源行逐字段解析并核对 page/block/quote。③ 反例：正文写 `[1]`、来源行没有 block，或引用 `[F009]` 但 evidence 没有 F009。

## 判定口径
core_definition:
① 取值/格式：core 由 B 逐条显式标注；凡会影响结论、比较、门槛或摘要的事实标 `true`，背景解释标 `false`。② A 的确定性判定：只按布尔字段筛选，核心事实必须至少出现一次合法引用。③ 反例：把所有事实都标 true 却不引用，或声称“模型自行判断核心”。
number_tolerance:
① 取值/格式：数值采用精确规范化比较，不设容差、不自动四舍五入；Decimal 解析后去除表示层前导零。百分比和小数不等价，`80–90%` 用区间对象，`3 组` 用数组；负数、科学计数法保留为 number，原文放 value_text。② A 的确定性判定：先比较 value 的结构和值，再比较 unit 的规范化字符串；结构、数值或单位任一不一致即报 NUMBER_MISMATCH/UNIT_MISSING。③ 反例：把 `85%` 与 `0.85` 自动视为相等，或把 `1.234` 四舍五入成 `1.23` 后放行。
citation_rules:
① 取值/格式：facts ID 必须连续无跳号；正文可以按任意顺序引用已存在 ID，同一 ID 可重复引用；未引用的非核心事实允许存在。② A 的确定性判定：检查声明 ID 是否恰为 `F001..Fn`；引用 ID 必须在集合中；核心集合每项至少被引用一次。③ 反例：facts 只有 F001、F003，缺 F002；或正文引用不存在的 F009。
```
