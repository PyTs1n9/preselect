# B1 字段与内容资产交付说明

本批以 B 身份交付字段语义、正文写法、五个提示词和五个质量夹具。没有修改 `pipeline/`、`tests/`、`schemas/`、`main.py`、`config.json` 或依赖文件。

## 1. 字段答复与 I3 同步项

12 项完整答复已写入 `.parallel/B-FIELD-REQUEST.md` 的答复区，对应关系如下：

| 编号 | 交付口径 |
|---|---|
| 1 | 顶层 `facts` 数组；每项是事实对象。 |
| 2 | `fact_id` 为连续唯一的 `F001`、`F002`……。 |
| 3 | `core` 为显式布尔值。 |
| 4 | `value` 支持 number、number 数组、区间 `{min,max}` 或 null；`value_text` 保留原表述。 |
| 5 | `unit` 支持字符串、与多值对应的字符串数组或 null；复合单位按完整字符串比较。 |
| 6 | `page_number` 与 `block_id` 统一为非空数组，跨页/跨块按源顺序保留。 |
| 7 | 正文首个非空行使用 `<!-- material_id: M1 -->`。 |
| 8 | 一个非空一级标题，章节逐字为「引言」「正文」「总结」「来源」。 |
| 9 | 正文引用 `[F001]`；来源节每行 `[F001] page=1 block=B003 quote=...`。 |
| 10 | `core` 逐条标注；核心事实必须至少被引用一次。 |
| 11 | 数值精确规范化比较，不设容差、不自动四舍五入；百分比与小数不等价。 |
| 12 | facts ID 不允许跳号；正文引用可任意顺序且可重复，引用必须存在。 |

建议 A 原样采用的 evidence 片段如下：

```json
{
  "properties": {
    "material_id": {"type": "string", "pattern": "^[A-Za-z0-9._-]+$"},
    "facts": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "required": ["fact_id", "core", "page_number", "block_id", "quote", "value", "unit"],
        "properties": {
          "fact_id": {"type": "string", "pattern": "^F[0-9]{3,}$"},
          "core": {"type": "boolean"},
          "page_number": {"type": "array", "minItems": 1, "uniqueItems": true, "items": {"type": "integer", "minimum": 1}},
          "block_id": {"type": "array", "minItems": 1, "uniqueItems": true, "items": {"type": "string", "minLength": 1}},
          "region": {"type": "array", "items": {"type": "object"}},
          "quote": {"type": "string", "minLength": 1},
          "value": {
            "oneOf": [
              {"type": "number"},
              {"type": "array", "minItems": 1, "items": {"type": "number"}},
              {"type": "object", "required": ["min", "max"], "properties": {"min": {"type": "number"}, "max": {"type": "number"}}, "additionalProperties": false},
              {"type": "null"}
            ]
          },
          "value_text": {"type": "string"},
          "unit": {
            "oneOf": [
              {"type": "string"},
              {"type": "array", "minItems": 1, "items": {"type": "string"}},
              {"type": "null"}
            ]
          }
        },
        "additionalProperties": false
      }
    }
  },
  "required": ["material_id", "facts"],
  "additionalProperties": false
}
```

这与 I3 当前表格存在明确差异：I3 只写“事实列表，每条含 `page_number`、`block_id`、`quote`”，没有写 `facts`、`material_id`、`fact_id`、`core`、`value`、`value_text`、`unit`，且默认单值定位。本批要求同步 I3 对应行，改为数组化定位并记录新增字段；A/B 按 §11 双签后再升 evidence schema 版本。B 本批没有直接写 `schemas/evidence.schema.json`。

## 2. 数值、正文与提示词

区间 `80–90%` 使用 `value: {"min": 80, "max": 90}`、`unit: "%"`、`value_text: "80–90%"`；多值使用 number 数组及等长 unit 数组；负数和科学计数法使用 JSON number；复合单位如 `mg/kg` 完整保留；无量纲可用 `倍` 或 null。A 侧按 Decimal 规范化后精确比较，百分比和小数不换算。

正文约定与现有 `validate.py` 对齐：来源节不计入正文汉字数；标题和四节不得编号或变体；writer 只使用 evidence；repair 只处理 `validation.json` 的 error issues。

已新增五个固定提示词，均为 UTF-8、LF、无 BOM、首行 `<!-- version: 1.0.0 -->`：

- `source_code/prompts/vision.md`
- `source_code/prompts/normalize.md`
- `source_code/prompts/evidence.md`
- `source_code/prompts/writer.md`
- `source_code/prompts/repair.md`

提示词不复制 `SKILL.md` 正文，不包含密钥形态或本机绝对路径；Skill 仍由 Codex 通过 SkillInput 路径加载。
