# 专业文献科普改写工具

读取指定专业材料，调用大模型生成中文 Markdown，保留证据记录，完成内容评审、格式检查和单个 ZIP 打包。参赛源码应反映真实生成流程；赛题允许对生成稿进行人工检查、修改和完善，修订时应如实保留记录。

本次源码更新不改动现有 `docs/` 四篇成稿。下次执行 `generate` 或 `all` 才会生成新版本。`review`、`validate` 不修改成稿；`package` 只读取当前稿件构建 ZIP。

## 安装与配置

使用 Python 3.10 及以上，无需 GPU。四份比赛材料均为 PDF，`requests`、`pypdf`、`fonttools` 均为必需依赖。

```bash
cd source_code
python -m venv .venv
# Windows PowerShell：.\.venv\Scripts\Activate.ps1
# macOS/Linux：source .venv/bin/activate
python -m pip install -r requirements.txt
```

2026-11-12 在独立 Windows 环境验证：Python 3.12.14、requests 2.34.2、pypdf 6.21.4、fonttools 4.68.0。`requirements-lock.txt` 保存这次验证环境的完整依赖版本，可用 `pip install -r requirements-lock.txt` 复现依赖；不保证跨 Python 版本逐字节相同的 PDF 抽取结果。

将四份原始 PDF 放到项目根的 `materials/`，保留材料编号，例如 `ges_docs_AI-01.pdf`。不要用自己选的材料代替。项目默认配置要求 `AI-01 / BIO-02 / IND-03 / MED-04` 四个编号全部存在。

复制 `.env.example` 为 `.env`，在本地填写 `LLM_API_KEY`。也可使用同名系统环境变量；系统环境变量优先。不要把密钥写进 Python、JSON、README 或测试。`.env` 与 `.env.*` 变体不会打包，只有空值 `.env.example` 模板可通过提交检查。

`config.json` 的 `llm.preset` 选择服务商预设；显式 `base_url/model` 优先。预设地址和模型名仅为配置示例，服务商可用性、模型权限及余额需要自行验证。程序使用兼容 Chat Completions 的接口，只接受 `finish_reason=stop` 的非空文本回复；结束原因缺失、长度截断、过滤或工具调用等不可用响应均会失败。生成还必须通过逐句证据覆盖核查，核查失败时不会发布原稿。

## 常用命令

```bash
python main.py doctor --offline   # 本地依赖、四份材料抽取和配置检查，不请求模型
python main.py doctor             # 上述检查，并真实调用一次模型验证连通性
python main.py generate           # 生成新一轮，成功验收后替换；保留旧稿备份
python main.py review --offline   # 本地数字风险与逐主张候选检索，不给内容分
python main.py review             # 全文分片取证、引文核验与模型评审，会调用API
python main.py validate           # 当前四篇格式、来源配置、源码与敏感内容检查
python main.py package            # 先验收，再构建和读回验证ZIP
python main.py all                # generate → validate → package
python -B -m unittest discover -s tests -v
```

不配置密钥仍可本地评审、验收和打包已有稿件；生成会明确停止，不自动用英文摘录覆盖中文成稿。程序保留 `generate_extractive` 作为显式调用的中文摘录草稿辅助函数，它不是主流程，也不承诺可提交质量。

## 生成怎样保证可检查

1. 先核对所有材料编号、依赖和配置，并读取全部材料。编号重复或材料不齐全时停止，不根据排序猜配、不自动改号。
2. 依据 `document.overrides.<编号>.document_type` 区分 `experiment`（也接受 `research`）、`review`、`perspective`；未知类型按 `auto/general` 保守处理。实验文关注设计和结果，综述关注证据范围和综合结论，观点文关注框架与待验证目标。
3. 短材料直接使用原文。超过 20000 字符时，按页分成约 10000 字符片段；先提取 JSON 事实，包含物理页码、原句、对象、指标、数值、单位、条件和结论强度。每段引文及摘录字段都必须在对应输入片段真实存在，坏引文最多重试一次，仍不合法即停止。
4. 合写时优先原文例子、重要数据和必要边界，减少次要缩写与参数。摘要未收录不能写成“原文未明确”；核心证据冲突返回待复核，禁止编造原文缺失的理由。
5. 生成后检查三节顺序、非空内容、中文和字数；缺节需依据证据修复，超长需压缩再验收，有限修复仍失败就停止。主入口随后依据本轮原文或事实记录核对对象、指标、结论强度、核心覆盖和表达；有意见最多修订一次并复核。核查意见中的引文也须真实存在，核心事实问题未关闭则停止。模型核查和引文定位都不保证语义无误，摘要之外的遗漏仍需全文评审。
6. 整轮在 `source_code/result/runs/<运行ID>/generated_docs/` 生成。全部合格后交换到 `docs/`；旧目录保存在同轮 `previous_docs/`。生成失败、材料在生成期间变化或现稿被同时修改时，不替换现稿。目录交换失败会尝试恢复旧目录；系统断电等异常情况下，可从运行目录中的备份恢复。

模型调用具有随机性；相同配置不保证逐字重现同一正文。`docs/_manifest.json` 会记录输入 PDF 文件 SHA-256、抽取文本指纹、输出文件 SHA-256、代码/配置哈希、依赖版本、模型参数和运行编号。事实记录保存在对应 `result/runs/` 中，供本地核验，不会打入提交包。输入指纹只能标识输入版本，不能证明改写准确或没有人工修订。

如需调整文章标题、来源、文献类型和目标长度，修改 `config.json`。当前目标为约 2000 字，生成提示留出余量；程序采用包含正文排版字符的保守口径，正文上限仍是 2500 字，一级标题与文末来源不计。配置标题在模型未输出一级标题时作为标题使用。

## 怎样读评审结果

官方权重为：科学准确性15、科普表达20、内容完整性20、格式规范性10、源码质量35。现有赛题没有提供每类错误的固定扣分表，所以程序不再按“警告扣1、错误扣2”伪造格式分，也不把文档分当比赛总分。证据足够且模型返回合规字段时，最多展示内容部分模拟小计 `/55`；格式和源码分别列证据，最终赋分由评委决定。

本地数字核对保留正负号、量级和单位，尝试关联局部指标；支持合法单位换算、小数四舍五入。日期、样本量等离散整数不得按百分比容差随意放宽。数字出现在全文其他地方不能验证当前说法，跨语种或上下文无法确定时标记待复核。它不是通用科学事实验证器。

`review --offline` 会逐主张搜索所有页面，提供原句与页码，并显示没覆盖的主张。中英文改写不一定有词汇重叠，候选覆盖可能较低；这意味着检索能力不足，不能推断原文没有。

在线 `review` 对全文分片扫描，将每条主张交给模型寻找支持、反证或限定原句；只接收对应片段、对应页真实存在的引文。默认每篇最多32次分片取证调用（客户端HTTP重试另计），之后再调用内容评审；实际调用次数取决于文本长度，费用和耗时也随之增加。达到调用上限、片段失败或上下文预算排除证据时，报告必须显示未覆盖，不悄悄以局部结果冒充全文核验。否定判断如“原文没有交代”、模型认为矛盾的主张仍需人工复核。

存在未覆盖项目时，不接受完整的科学准确性/内容完整性数字评分；保留具体问题和证据。评审报告保存到 `source_code/result/review_*.md`。提高分数应通过修正事实、解释术语和补齐重要边界，不能通过放宽评审提示词实现。

## 打包与最终核查

提交包顶层为四篇 `<材料编号>.md`、`提交说明.md` 和 `source_code/`。源 PDF、内部 manifest、证据中间产物和历史评审不打包。源码可按实际功能分文件，不需要为比赛增加复杂界面或多智能体框架。

打包采用临时 ZIP：先检查输入，再读回包内实际字节并与当前文档逐份比对；发现旧稿、重复/不安全路径、敏感文件或输入在打包期间变化时拒绝发布，保留上一份成功 ZIP。`.env` 不进入包，`.env.example` 中即使在注释里出现匹配的疑似密钥也会被拒绝。

格式检查通过仅说明已检查的硬性要求未报错；来源真实性、研究结论、读者理解程度仍应对照原文。PDF 的图、复杂表格与公式可能没有完整文字层，需要逐页视觉核验。现有稿如按赛题允许做人工修订，应如实更新生成说明并保留差异，而不是继续声称“未经人工改写”。

## 代码导航与回归检查

| 文件 | 职责 |
|---|---|
| main.py | CLI、预检、运行记录、保留旧稿、评审与打包编排 |
| pipeline/extractors.py | 格式抽取、物理页码、材料编号与文本指纹 |
| pipeline/prompts.py / generate.py | 类型化写作、事实引文校验、有限修复、响应验收 |
| pipeline/evidence.py / review.py | 全文候选定位、在线引文校验、数字风险和内容评审 |
| pipeline/contracts.py / validate.py | 共享文档硬性规则及提交输入校验 |
| pipeline/package.py | 临时ZIP、逐份内容核验、敏感文件排除、成功后替换 |
| pipeline/settings.py | 本地环境变量和服务商配置 |

测试包含原模块行为及实际漏洞回归：半轮失败保留成稿、用户同时编辑不覆盖、目录交换失败回滚；假引文、错页、截断响应、压缩丢章节；指标串位、单位/量级错误、负号与年份；材料错配、空章节和旧ZIP。全部测试不调用真实API。运行时以测试输出的数量为准，不把测试数量当成质量评分。
